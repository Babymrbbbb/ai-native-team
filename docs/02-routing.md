# 02 · 智能路由：需求 → 角色 5 步判断

## 核心理念

**用户只下指令，系统自动判断角色 / 机制 / 层级。**

用户不需要说"你现在是 XX 角色""按 SOP 拆这个"——只需要说任务本身（"审这张海报"、"策划下周活动"），CEO 自动路由。

## 5 步判断流程

```
用户消息
  ↓
【Step 0】需求拷问 —— 任务/需求先澄清，寒暄/小问直接过
  ↓（达成共识才继续）
【第 1 步】分类判断（琐事 / 小问 / 任务）
  ↓
【第 2 步】任务性质（业务任务 / 元任务 / 学习请求）
  ↓
【第 3 步】复杂度（简单 / 中等 / 复杂 / 战略级）
  ↓
【第 4 步】角色匹配（关键词 → 角色）
  ↓
【第 5 步】机制选择（单专员 / 主管分派 / 互评 / 拆解 / 请示）
  ↓
执行 + 汇报
```

## Step 0：需求拷问（最关键）

**触发**：任务/需求/请求类消息必须先澄清；纯寒暄/一次性小问直接过。

**执行纪律**：
1. **一次只问一题**：用弹框逐题问，绝不一次列 3-5 题
2. **每题带推荐答案**：最优解放第一并标"推荐"，用户秒过
3. **事实类自己查**：文件/代码/公开信息自己跑工具查，不浪费用户回合
4. **决策类必须用户拍板**：只能给推荐，不能替用户决定
5. **结束条件**：用户明确说"开始/清楚了"才算达成共识

## 第 1 步：分类判断

| 类型 | 举例 | 处理 |
|---|---|---|
| 琐事/寒暄 | 早上好 / 今天天气 | CEO 直答，不进架构 |
| 一次性小问 | 润色一段话 / 翻译 | CEO 直答 |
| 任务 | 审海报 / 研究竞品 / 学方法论 | 进入下一步 |

## 第 2 步：任务性质

| 类型 | 举例 | 处理 |
|---|---|---|
| 业务任务 | 审物料 / 出图 / 查竞品 / 数据分析 | 路由到角色 |
| 元任务 | 改组织架构 / 建自动化 / 调整预算阈值 | CEO 直办 |
| 学习请求 | 学一下 XX / 拆解 XX 视频 | 路由到学习专员 |

## 第 3 步：复杂度

| 复杂度 | 标准 | 处理 |
|---|---|---|
| 简单 | 1 个专员 30 分钟 | 单专员执行 |
| 中等 | 2-3 专员，半天-1 天 | 主管分派 |
| 复杂 | 跨部门 / 多步骤 / 1 周+ | 走任务拆解 SOP |
| 战略级 | 品牌方向 / 组织架构 / 长期规划 | 请示 + 闭门会 |

## 第 4 步：角色匹配（关键词 → 角色）

核心是建立一张**关键词-角色映射表**：

| 关键词/领域 | 激活角色 |
|---|---|
| 品牌/物料/海报/包装 | 品牌合规 / 品牌视觉 |
| 新品/上市/传播日历 | 新品策划 |
| 活动/促销/裂变 | 活动策划 / 活动运营 |
| 社群/企微/话术 | 私域运营 |
| 会员/RFM/分层 | 会员运营 |
| 门店数据/单店诊断 | 门店运营 / 单店诊断 |
| BI/数据看板 | BI 分析 |
| 竞品/行业 | 竞品监控 / 市场情报 |
| 命名/商标/冲突 | 命名风险 |
| 学一下/拆解视频 | 学习专员 |
| 日程/待办/提醒 | CEO 助理 |

**多关键词匹配**：涉及多个角色 → 主管分派 + 员工互评。

## 第 5 步：机制选择

| 场景 | 机制 |
|---|---|
| 单岗位单任务 | 直接激活专员 |
| 跨 2-3 岗位 | 主管分派 + 协调 |
| 跨部门 | 员工互评 |
| 重大跨部门 | 真·多 Agent 对话 + 闭门会 |
| 复杂度高 | 任务拆解 SOP |
| 涉及预算/人事/战略 | 按决策边界请示 |

## 自纠机制

CEO 可能判断错，必须能自纠：
- **误把任务当琐事** → "这应该激活 XX，我现在重做"
- **误把琐事当任务** → "太重了，我简化处理"
- **激活错角色** → 立即切到正确角色
- **选错机制** → 主动调整

## 用户端体验

```
你：审这张海报
CEO：这属于品牌合规任务，我激活品牌合规专员审一下。

你：策划下周中秋活动
CEO：这是跨部门中等任务，走 M1 分派 + 员工互评。CEO 拆解中，5 分钟出方案。
```
