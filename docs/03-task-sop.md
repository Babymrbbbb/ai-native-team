# 03 · 任务拆解 SOP：三层拆解

## 核心理念

**不接单不执行，接单必拆解，拆解必审核。**

```
老板下达指令
  ↓
【CEO 层】→ 项目级 → 大方向 → 定 3-5 个战略选择
  ↓
【主管层】→ 项目级 → 动作级 → 定 5-15 个具体动作
  ↓
【专员层】→ 动作级 → 步骤级 → 具体执行步骤
```

## CEO 层拆解 SOP

### 5 步流程

1. **需求澄清（10 分钟）**：复述指令，确认理解；询问目标/时限/预算/优先级
2. **项目定调（15 分钟）**：一句话定义目标、边界、成功标准
3. **多角度拆解（30 分钟）**：用 5 维拆解框架，每维度列 2-3 方案
4. **审核评估（30 分钟）**：用 5 维审核标准评分，选出 2-3 候选
5. **定大方向 + 请示（10 分钟）**：涉及边界请示，否则自决 + 分派主管

### 5 维拆解框架

| 维度 | 核心问题 |
|---|---|
| 战略对齐 | 与品牌/公司战略一致吗？ |
| 业务影响 | 影响哪些部门/客户/员工？ |
| 资源需求 | 需要多少人/钱/时间/工具？ |
| 时间成本 | 多久能做？分几个里程碑？ |
| 风险与协同 | 有什么风险？需要谁配合？ |

### 5 维审核标准（每个方案 1-5 分）

| 维度 | 5 分 | 1 分 |
|---|---|---|
| 战略 | 完全对齐 | 与战略冲突 |
| 影响 | 明显正向 | 负面影响大 |
| 资源 | 资源充足 | 严重不足 |
| 时间 | 时间充裕 | 严重不足 |
| 风险 | 风险低 | 风险高 |

## 主管层拆解 SOP

### 4 步流程

1. **拆解到动作级（30 分钟）**：每个大方向拆到 3-10 个动作，明确负责人/时间/交付物/验收标准
2. **分派到专员（20 分钟）**：每个动作分给合适专员，明确依赖与协作接口
3. **制定里程碑（10 分钟）**：项目分 3-5 个里程碑，各有验收标准
4. **主管审核（15 分钟）**：检查是否符合大方向、是否可执行、资源是否匹配

## 专员层拆解 SOP

### 3 步流程

1. **拆解到步骤级（20 分钟）**：每个动作拆到 3-10 步，每步明确做什么/用什么工具/花多少时间
2. **预估时间（10 分钟）**：每步预估耗时，汇总对比主管要求是否有 buffer
3. **遇到卡点立即上报（随时）**：技术卡点→主管；跨部门依赖→主管协调；战略模糊→CEO

## CEO 项目总控看板

每个项目必须有总控看板，CEO 每周更新：

```markdown
# 项目 [名称] 总控看板 · YYYY-MM-DD

## 项目状态：进行中/已完成/已延期/已暂停

## 里程碑进度
| 里程碑 | 计划 | 实际 | 状态 |
|---|---|---|---|
| T+3 | xxx | xxx | ✅/⏳/❌ |
| T+7 | xxx | xxx | ✅/⏳/❌ |

## 各部门动作完成度
- M1：x/y（xx%）
- M2：x/y（xx%）

## 关键风险
- xxx（等级：高/中/低）

## 待 CEO 决策
- xxx

## 请示老板
- [ ] 是 / [ ] 否
```

## 拆解纪律

1. 不接单不执行：没拆解就不开始
2. 拆解必审核：CEO 过 5 维审核，主管过 4 项检查
3. 拆解必记录：所有拆解写入项目目录
4. 拆解必有里程碑：无里程碑不算拆解
5. 拆解必有产出：拆解本身就要产出方案文档
6. 卡点立即上报：不藏着掖着
7. 拆解不重复：已拆解的项目只更新看板，不重复拆
