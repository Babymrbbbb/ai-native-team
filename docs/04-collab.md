# 04 · 协作机制：互评 / 闭门会 / 过审 / 请示

## 核心理念

4 个机制串联团队协作：**员工互评 → 主管闭门会 → CEO 过审 → 老板请示**。

## 一、员工互评（跨部门任务必触发）

### 触发条件
- 跨 2+ 部门任务
- 主管无法单独决策的议题
- CEO 主动要求评审

### 流程
```
1. CEO 分派跨部门任务 → 指定主责部门
2. 主责主管拆解，通知其他主管"需要评审"
3. 其他主管派代表专员参与评审（1 人代表 1 视角）
4. 每个评审专员输出"从自己角度"的评审意见
5. 主责主管收集所有评审 → 多视角评审报告 → 提交 CEO
6. CEO 决定是否进入闭门会
```

### 硬约束
1. **评审必带角度**："我的角度是 X，从 X 角度看这个问题..."
2. **至少 2 个不同部门视角**：少于 2 视角不算评审
3. **评审不删改原始意见**：保留分歧，冲突由主管在闭门会解决
4. **评审不越权**：专员只给意见，不决策

## 二、部门主管闭门会（每周三）

### 参会
- 必到：6 位主管 + CEO
- 可列席：议题相关专员
- 时长：1 小时封顶

### 议程（60 分钟）
| 时段 | 环节 | 内容 |
|---|---|---|
| 0-5 min | CEO 开场 | 本周重点、跨部门冲突预警 |
| 5-35 min | 主管轮流汇报 | 每人 5 分钟（已完成/下周计划/需决策/需协作） |
| 35-55 min | 跨部门议题讨论 | 逐项过评审、协调分歧、形成联合方案 |
| 55-60 min | CEO 决策 | 批准/修改/退回，重大议题请示老板 |

## 三、CEO 过审流程

### 触发
- 主管提交"部门联合方案"
- 主管提交"部门周报"
- 主管请示（无法决策时）

### CEO 动作流程
```
1. 阅读方案 → 判断是否达提交标准
   ├─ 不达标 → 退回并写清理由
   └─ 达标 → 进入 2
2. 判断影响范围：
   ├─ 单部门内 → 直接批准
   ├─ 跨 2-3 部门 → 协调后批准
   └─ 跨 4+ 部门 / 预算/人事/战略 → 进入 3
3. 请示老板
   ├─ 批准 → 通知执行
   ├─ 修改 → 按修改意见调整后执行
   └─ 退回 → 通知主责主管重做
```

### 过审 SLA
- 单部门内方案：CEO 24 小时内回复
- 跨部门方案：CEO 48 小时内回复
- 请示老板：CEO 立即请示，不拖

## 四、请示机制

### 触发条件（硬约束）
1. **预算**：> 阈值
2. **人事**：招人 / 晋升 / 淘汰
3. **战略**：品牌方向 / 市场进入 / 门店开闭
4. **对外承诺**：合作方签约 / 重大公开声明
5. **CEO 无法决策**：跨 4+ 部门 / 重大不确定性

### 请示报告格式
```markdown
# 请示报告 · [主题]

## 背景
[情况描述]

## 可选方案
- 方案 A：xxx（优点/风险/成本）
- 方案 B：xxx（优点/风险/成本）
- 方案 C：xxx（优点/风险/成本）

## CEO 建议
推荐方案 X，理由：xxx

## 需要您决策
- xxx

## 时限
建议在 YYYY-MM-DD 前决策，因为：xxx
```

## 五、预算审批规则

| 金额档 | 决策权 | 报备 | 请示 |
|---|---|---|---|
| ≤ 1 万 | CEO 自主批准 | - | - |
| 1 - 5 万 | CEO 决策 | 事后报备老板（48h 内） | - |
| 5 - 10 万 | CEO 请示 | - | 老板批准 |
| > 10 万 | 老板决策 | CEO 组织闭门会 | 老板批准 |

## 六、7 条铁律

1. **老板只对接 CEO**：不做具体执行
2. **CEO 只做调度+审核+升级**：不越级指挥专员
3. **主管只做本部门管理**：不跨部门指挥
4. **专员只做本岗执行**：不擅自决策
5. **学习专员是知识源**：知识包定向分发
6. **员工互评是硬要求**：跨部门任务至少 2 视角评审
7. **闭门会 + 过审 + 请示**：跨部门方案必须走完三步

## 七、内部讨论机制（进阶）

所有任务执行前先过一轮讨论，重大议题用真·多 Agent 对话：

| 模式 | 适用 | 实现 | 成本 |
|---|---|---|---|
| A 讨论纪要格式 | 日常任务 | CEO 模拟多角色发言 | 低 |
| C 真·多 Agent 对话 | 战略级/跨 4+ 部门/预算 >5 万 | Spawn 3-6 子 Agent 实时讨论 | 高 |

**硬约束**：
1. 至少 2 个视角：主责 + 至少 1 个不同部门视角
2. 必须有分歧：全是同意 = 无效讨论
3. CEO 必裁决：讨论完必须明确裁决，不能"再议"
4. 记录可追溯：讨论纪要落盘存档
