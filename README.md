# AI-Native Team OS

> 一套真实运行过的「AI 原生组织」操作系统：1 个老板 + 数十个 AI Agent 角色 + 多个 AI 工具协作，通过智能路由、任务拆解、协作评审、自动化调度，把模糊业务诉求转成可量化业务结果。
>
> 本文档是通用化、脱敏后的方法论版本。原体系在某连锁零售品牌真实运行，已覆盖 40+ 自动化任务、数十个角色、多部门协作、多 AI 工具真实分工（总监/员工/人工精调三层）。

> 📌 **技术关键词**：Agent 编排 / 多智能体 / Skill 体系 / 工作流 / MCP 工具集成 —— 覆盖多智能体协作与工作流编排的完整落地路径。

## 为什么做这个

AI 落地真正的瓶颈不是"模型不够强"，而是**组织怎么消化 AI**。单个 Prompt 写得好只能解决单个问题；要让 AI 持续产出业务结果，需要一套可运行的组织机制：

- 谁负责什么、谁能决策什么
- 需求来了怎么路由到正确的角色
- 任务怎么拆解、怎么审核、怎么验收
- 跨部门怎么协作、冲突怎么裁决
- 知识怎么学习、沉淀、复用
- 自动化怎么调度、怎么防止失控
- **多个 AI 工具怎么物理分工、怎么防止互相覆盖**

本仓库把这一套机制以**通用化、脱敏后的方法论**形式公开，分 11 个模块。生产实现（含品牌专属角色、自动化任务实例）为独特自研改造，不对外开源。

## 核心概念速览

| 概念 | 一句话 |
|---|---|
| **智能路由** | 用户只下指令，系统自动判断角色/机制/层级 |
| **三层拆解** | CEO 拆方向、主管拆动作、专员拆步骤 |
| **员工互评** | 跨部门任务至少 2 个视角评审，冲突留到闭门会 |
| **决策边界** | ≤1 万自决、1-5 万报备、>5 万请示 |
| **自动化** | 44 个定时任务覆盖 晨会/周报/巡检/学习/竞品 |
| **四闸校验** | 填写闸/术语闸/驳回闸/反勾结闸 —— 防 AI 产出空壳件 |
| **多工具协作** | 总监写码验收 / 员工执行 / 人工精调 UI，文件夹物理隔离 |
| **蓝图门禁** | 搭系统前必须先出一页蓝图、老板终审，再拆任务单 |
| **真调验收** | 验收必须由总监 CLI 真实执行，严禁"同款模型扮演总监" |

## 围绕同一场景改造出的配套产出

> **核心**：围绕「45+ 家门店 AI 落地」场景，按真实故障逐步改造成 5 个公开项目 + 2 个桌面软件。每个产出解决一个具体故障。

```
接入 AI（gateway）→ 用好 AI（prompt-craft）→ LLM×RAG 知识库（llm-wiki）→ 组织 AI 落地（本仓库）→ 交付业务结果（驾驶舱 / 运维工作台）
```

### 本仓库在场景中的位置

**为什么改造**：AI 能力很多（网关能调模型、提示词能产内容、知识库能存知识），但**组织消化不了**——谁负责什么、任务怎么拆、怎么验收、多个 AI 工具怎么不互相覆盖。不改，AI 就是零散工具拼盘，不是生产线。

**意义**：把「AI 工具」升级为「AI 组织」——智能路由、三层拆解、四闸校验、蓝图门禁、真调验收，让多个 AI 角色像团队一样协作，产出可验收的业务结果。

**结合哪些部分**：
- 调度 **sensenova-gateway** 的模型配额，支撑 44 个自动化任务
- 编排 **prompt-craft** 的内容生产工作流
- 驱动 **llm-wiki** 的知识库每日维护自动化
- 产出结果落到 **驾驶舱 / 运维工作台** 交付给业务方

**单独用的价值**：即使不接入其他产出，任何想「让多个 AI Agent 协作干活」的团队都能直接用这套组织机制——角色分工、任务拆解、质量门禁、防失控。
